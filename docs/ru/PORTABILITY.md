# Переносимость

Английский оригинал: [PORTABILITY.md](../PORTABILITY.md).

Сдача должна работать на машине Linux x86-64, отличной от той, где её собирали,
поэтому набор проверяется в чистых контейнерах, а не только на хосте разработки.
Эта страница фиксирует, что проверялось, как и с каким результатом. Она покрывает
требование R5 (воспроизводимый перенос) на уровне окружения.

## Цель

- Linux x86-64.
- Python 3.12 или новее.
- Никаких системных сервисов и никакой сети во время работы; каждая команда
  выполняется офлайн.

## Ревизия сдачи (794 теста)

## Docker

`Dockerfile` и `scripts/test_in_docker.sh` предоставлены, но демон Docker
недоступен в окружении, где проверялась эта ревизия, поэтому контейнерный путь
подготовлен и здесь не перезапускается. Строки чистой распаковки выше используют
настоящий интерпретатор 3.12 на хосте как эквивалентную проверку. На хосте с
Docker `scripts/test_in_docker.sh` гоняет тот же набор и стартовый линт в
одноразовом образе Ubuntu.

## Что делает каждая проверка

`scripts/test_in_docker.sh` копирует рабочее дерево в образ, ставит закреплённые
зависимости в виртуальное окружение и запускает набор. Он принимает образ и версию
Python, поэтому один скрипт покрывает оба конца поддерживаемого диапазона:

```
scripts/test_in_docker.sh                 # ubuntu:22.04, python 3.12
scripts/test_in_docker.sh ubuntu:24.04 3.13
```

Дистрибутивный Python на Ubuntu 22.04 — 3.10, поэтому скрипт добавляет PPA
deadsnakes, когда запрошенный интерпретатор не дистрибутивный. Шаги сборки
сцеплены в одну строку `RUN`, чтобы Dockerfile оставался одной инструкцией. Скрипт
использует демон Docker напрямую, когда текущий пользователь может дотянуться до
сокета, и откатывается к `sudo -n`, когда не может.

## Зависимости в чистом окружении

- `PySide6==6.8.1` ставится из колеса `manylinux_2_28`, которому нужен glibc 2.28
  или новее. Ubuntu 22.04 и 24.04 обе удовлетворяют этому. Ни сборочных
  инструментов, ни компилятора, ни системного Qt не требуется; колесо несёт
  библиотеки Qt.
- `dpkt==1.9.8`, `PyYAML==6.0.2` и закреплённые инструменты разработки ставятся
  без ошибок.
- Ни одна установка не предупреждает и не падает ни на одной версии Python.

сборка падает, а не отправляется без него.

## Находки

Дефекта переносимости окружения не найдено; единственный дефект содержимого архива
— пропущенный каталог `examples/`, записанный выше. Две заметки стоит сохранить:

- `git` отсутствует в минимальном контейнере. Сборщик сдачи читает автора из
  `git config` при отрисовке манифеста и трактует отсутствующий `git` как пустую
  личность, а не падает, поэтому сборщик работает и в урезанном окружении.
- Набор не должен зависеть от рабочего дерева. Он и не зависит: корпус и
  эталонные выгрузки закоммичены, а `scripts/generate_corpus` пересобирает их
  детерминированно при необходимости.

## Воспроизведение без Docker

Там, где Docker недоступен, чистое виртуальное окружение на любом хосте Linux
x86-64 воспроизводит проверку:

```
git clone https://github.com/Pavel1778/madrigal-protocol-lab.git
cd madrigal-protocol-lab
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -e ".[dev]"
pytest tests/ -q
```

Ожидается: набор проходит. Затем прогоните проход из `docs/USAGE.md`.
