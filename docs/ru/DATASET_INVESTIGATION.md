# Исследование предоставленных захватов

Английский оригинал: [DATASET_INVESTIGATION.md](../DATASET_INVESTIGATION.md).

Набор захватов организатора нормализуется тем же путём, что использует приложение
(`src/capture/pipeline.py`), и читается обратно через контракт захвата, поэтому эти
числа описывают поставляемые файлы и поставляемый код, а не фикстуру.

## 1. Исследовательские захваты

Правило запроса (`examples/thermostand_request_v2.json`) и правило ответа
(`examples/thermostand_response_v2.json`) применяются к каждому исследовательскому
захвату. `not_applicable` считает сообщения, которые несёт другое направление,
поэтому чистый захват сообщает только `matched`.

Запросы:

| захват | matched | mismatched | incomplete | not_applicable |
| --- | --- | --- | --- | --- |
| 01_configuration.pcap | 14 | 0 | 0 | 14 |
| 02_variations.pcapng | 15 | 0 | 0 | 15 |
| 03_combined_messages.pcap | 8 | 0 | 0 | 8 |
| 04_new_observations.pcapng | 8 | 0 | 0 | 8 |

Ответы:

| захват | matched | mismatched | incomplete | not_applicable |
| --- | --- | --- | --- | --- |
| 01_configuration.pcap | 14 | 0 | 0 | 14 |
| 02_variations.pcapng | 15 | 0 | 0 | 15 |
| 03_combined_messages.pcap | 8 | 0 | 0 | 8 |
| 04_new_observations.pcapng | 8 | 0 | 0 | 8 |

Ни одно сообщение не mismatched, incomplete или ambiguous ни в одном
исследовательском захвате. Два исключения в потоке ответов захвата вариаций —
ответы об ошибках (`value_out_of_range`, `malformed_body`): они несут однобайтовое
тело, поэтому поля конфигурации после статуса корректно вне сообщения, и поля,
принадлежащие успешному ответу, не применяются.

## 2. Уточнение по контрпримеру

Первое чтение (`examples/thermostand_request_v1.json`) предполагает, что поле длины
считает только нагрузку и что сообщение начинается с первого байта поля длины.
Применённое к захвату конфигурации:

| правило | matched | mismatched | incomplete |
| --- | --- | --- | --- |
| v1 (длина только нагрузки) | 0 | 2 | 4 |
| v2 (длина включает четырёхбайтовый заголовок) | 14 | 0 | 0 |

Контрпримеры, которые производит v1, каждый привязан к своим байтам:

| статус | поле | причина |
| --- | --- | --- |
| incomplete | message_counter | field_beyond_message |
| mismatched | magic | value 1 not in expected [42588] |
| incomplete | magic | payload_truncated |
| incomplete | message_counter | field_beyond_message |
| mismatched | magic | value 1 not in expected [42588] |
| incomplete | magic | payload_truncated |

Исправление — четырёхбайтовое смещение заголовка во фрейминге длины, которое v2
несёт как `length_bias`. Контрпримеры — это доказательство: первое сообщение под v1
сфреймлено на четыре байта короче, поэтому магия читается по неверному смещению, а
счётчик попадает вне сообщения.

## 3. Диагностические захваты

Каждый диагностический захват построен, чтобы упражнять один режим отказа.
Диагностики ниже — то, что пересборщик действительно сообщает.

| захват | упражняет | сообщённые диагностики |
| --- | --- | --- |
| 01_retransmission.pcap | ретрансмиссию | нет |
| 02_reordered.pcapng | доставку не по порядку | нет |
| 03_missing_segment.pcap | недостающий сегмент | gap |
| 04_snaplen_truncated.pcapng | обрезанный снимок | gap |
| 05_conflicting_overlap.pcap | конфликтующее перекрытие | ambiguity |
| 06_missing_beginning.pcapng | соединение без начала | нет |
| 07_checksum_offload.pcap | checksum offloading | нет |
| 08_bad_checksum.pcapng | неверную контрольную сумму | нет |

Проверка контрольных сумм выключена по умолчанию, поэтому `07_checksum_offload.pcap`
сообщает `none`. С `--verify-checksums` он сообщает `checksum_offload`.

## 4. Корреляция с журналом

Журнал действий держит 109 записей. Раскодированные запросы коррелируются так:
14 из 14 сообщений скоррелированы, 95 записей журнала не сопоставлены

Корреляция привязывает каждое сообщение-запрос к выполняемому им действию оператора
и подтверждает раскодированные параметры по записанным значениям, так что имя поля —
не просто правдоподобная метка.

## 5. Откуда берётся набор

Состав и происхождение данных записаны организатором в
`tests/corpus/real/dataset_manifest.json`: ожидаемые счётчики сессий и действий на
исследовательский захват и утверждение, что байты приложения приходят из реального
TCP-обмена клиента/симулятора через сокет, тогда как фрейминг Ethernet/IP/TCP,
сегментация и часы сгенерированы. Конвейер воспроизводит записанные счётчики сессий
(2, 1, 1, 1) точно, а восемь диагностических захватов несут каждый одно условие
захвата или целостности. Полный анализ — в `docs/REAL_CORPUS_ANALYSIS.md`.
