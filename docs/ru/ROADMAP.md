# План развития

Английский оригинал: [ROADMAP.md](../ROADMAP.md).

Что реализовано, что осталось вне MVP, технический долг и что добавил бы ещё один
месяц.

## Реализовано

Требования R1–R6 из задания, закрытые кодом:

| Требование | Состояние | Где |
| --- | --- | --- |
| R1 исходный обмен: PCAP/PCAPNG, сессии, направления, пересборка, провенанс, диагностики | сделано | `src/capture/` |
| R2 средства исследования: поиск, сравнение, hex-просмотр, журнал действий | сделано | `src/capture/`, `src/ui/` |
| R3 интерпретации: декларативные правила, версионирование, переиспользование на новых данных | сделано | `src/protocol/`, `src/hypothesis/` |
| R4 проверка: корпус, контрпримеры, видимая область применимости, повторная проверка | сделано | `src/hypothesis/` |
| R5 переносной проект: относительные пути, манифест, версии, результаты | сделано | `src/project/` |
| R6 переиспользование: отчёт (Markdown/HTML), машиночитаемый результат (JSON), CLI | сделано | `src/report/`, `src/*/cli.py` |

## Вне области MVP

Расширения, которые называет задание и которые не построены, с причиной и формой,
которую приняла бы первая версия.

| Расширение | Почему отложено | Первая версия |
| --- | --- | --- |
| Объяснимые предложения шаблонов: предлагать раскладки полей, которых исследователь не задавал | Нужен поиск по смещениям, ширинам и чтениям, а это отдельный проект; текущий инструмент оценивает чтения, которые даёт исследователь | Перебрать кандидаты границ полей по сфреймленным байтам и ранжировать по поддержке/противоречию, переиспользуя существующую оценку |
| Автоматическое связывание запроса и ответа | Нужно правило ответа, которое не выведено; корпус несёт оба направления, но интерпретируется только направление запроса | Сопоставлять по id транзакции или по окну времени, затем проверять соответствие полей |
| Сравнение поведения между захватами | Корпус — один протокол; для осмысленного сравнения нужен второй протокол | Сравнивать два проекта по версии правила и по счётчикам сообщений |
| Сложные структуры: вложенные, переменной длины, повторяющиеся поля | Схема правил — плоские поля; вложенность изменила бы схему | Вид поля `list` с полем-счётчиком и дочерней раскладкой |
| Контролируемые эксперименты: изменить один байт и наблюдать | Нет живого объекта; захваты записаны | Действие проекта, переписывающее сообщение и перезапускающее правило |

## Технический долг

| Пункт | Влияние | Путь |
| --- | --- | --- |
| зашифрованные нагрузки | вне области по замыслу | нет; инструмент сообщает байты, которые видит |
| память масштабируется с захватом | все пакеты держатся сразу | разбор сессия за сессией с провенансом, пишущимся на диск (см. `docs/BENCHMARK.md`) |
| форматирование и типизация отложены | `ruff format --check` и `mypy` всё ещё сообщают находки в модулях вне проверяемой зоны (сам расширенный набор `ruff` включён) | снова включить `ruff format --check .` и `mypy .` по одной зоне за раз (см. `docs/AUDIT.md`) |

## Продуктовый план на ещё один месяц

1. Вывести правило ответа, затем связать запросы с ответами по id транзакции;
   корпус уже держит оба направления.
2. Предложение шаблонов: искать границы полей и ранжировать чтения, чтобы
   исследователь начинал с предложений, а не с пустого правила.
3. Второй протокол в корпусе, чтобы сравнению поведения было что сравнивать, а
   граница применимости упражнялась на настоящем разбросе.
4. Режим с ограниченной памятью по умолчанию: разбирать и пересобирать сессия за
   сессией, записывая провенанс по мере получения.
5. Сборка фрагментов (IPv4 и IPv6) в слое захвата.
